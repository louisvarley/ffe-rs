# System generation (F872-F897)

`ffe_core::sysgen`, `ffe_core::handcoded` (generated by `tools/gen_handcoded.py`
from F875), `ffe_core::ffp`. Data: the cache's `base:world/system-tables`.

F878 builds a system's list of **68-byte objects** (stars, planets, moons,
stations, starports) from a seed pair, the total mass (also the second seed), a
star count and the system code. A zero first seed selects a **hand-coded**
system. Object layout: `+0` mass (ffp), `+4` seed, `+8` parent (1-based), `+0xa`
type, `+0xc` model, `+0xe` orbit radius (ffp), `+0x12` start angle, `+0x14` orbit
velocity (ffp), `+0x1c` light, `+0x22` longitude, `+0x24` temperature, `+0x26`
name (20 bytes), `+0x3e` rotation speed, `+0x3f` depth (bit 7: named), `+0x42`
orientation.

- **F894** is the generator's random number: `b += a; a = rotl(a_old,3) + sum +
  rotl(sum,5)` with `sum = a + b` (the csysgen notes' version of the rotate is
  wrong; the assembly is followed throughout).
- **F881** picks the class by the mass thresholds (`DATA_007121`), copies its
  type, model, temperature and light, names it (only F893's flag matters), runs
  F882 and the class handler (F883 rocky, F884 small rocky, F885 barren, F886
  small barren, F887 asteroid, F888 red giant, F889 yellow, F890 white).
- **F882** sets the orbit (F1515 of two parameters, to ffp, +0x19 exponent;
  Kepler's `sqrt(r^3 / parent mass) * 0x5edb >> 15`), the seed, mass, angles
  (two squares whose high parts are mostly zero: `+0x20` is always 0 and `+0x42`
  is 0 or 0xffff) and the temperature, warmed by every star above it.
- **F877** makes a star pair (or, for odd masses, a barycentre with two stars; JJFFE
  fixes the barycentre's light), **F897** recursively places planets by the
  spacing table (`DATA_007129`) and its random draws, **F891**/**F892** add
  starports and stations from the hand-coded templates (objects 2, 12, 16 and
  17 of the F875 array).
- **F875** builds the 146 hand-coded objects (Sol and the neighbourhood) from 133
  calls of F873/F874 with F872's two-seed generator.
- The hand-coded path converts a run of those objects (selected through
  `DATA_007133`, default 143) to the generated form and leaves the random state
  alone.

## What is not generated

Names. Stars are the system name, a space and a letter (`A`, `B`...); the centre of an
opposing-orbit pair is `Name A,B` (a `.` instead of the space when the name is longer
than 11); a planet is its parent's name and a counter (digits at the first level, `a`...
at the second, digits again below), the counters being F897's own parameters copied down
by value to the next level; anything whose parent is already a generated name (moons of
named planets, starports, stations) goes through F893 and the name generator
(`docs/notes/names.md`). Compared up to the NUL (the original leaves stale bytes after
it). Not reproducible: F877 keeps its counters in uninitialised locals, so the first star
of a pair whose mass is below a star's (possible when the total mass is under twice a
star's) gets a counter from stack garbage; the port starts them at zero, records those
objects (`Generator::uncertain`) and the tests leave them and the names built from theirs
out of the comparison, as they do the accented letters JJFFE's data spells differently.
Everything else is byte-exact.

## Oracle

`--sysgen`: first the 146 hand-coded objects, then 4,096 synthetic systems (star
masses from 17,000,000 up, 0 to 7 stars, random codes, populations up to 255) and
64 hand-coded ones, all compared byte for byte with names zeroed: 4,156 systems,
63,810 objects, 0 mismatched. Four parameter sets make the original loop forever
(a timer skips them). Every tampered field and an empty trace are rejected.
